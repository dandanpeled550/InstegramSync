# M0 — Setup

**Goal:** the repo, tooling, contracts and accounts are ready, so M1 can start building the receiver.
**Done when:** the first PR merged into `dev` passes CI, and release `v0.1.0` is merged into `main`.

## Bootstrap (done directly on `main` — the only direct commit in this repo's life)

- [x] Repo with `main`; `CLAUDE.md`; `.claude/` agents, hooks, skills, settings, ownership, gates
- [x] `.gitignore`, `.env.example`, PR template, pre-commit config, `CONTRIBUTING.md`, `SECURITY.md`, `LICENSE`
- [x] `docs/` skeleton with `PLAN.md` and `AGENTS_PLAN.md`
- [x] `dev` branch created from `main`

## Human steps

- [ ] **HUMAN H1** — Create the GitHub repo (public), push `main` and `dev`, set `dev` as the default branch,
      run `git remote set-head origin dev`.
- [ ] **HUMAN H2** — Install tools: Supabase CLI, Deno, `uv` (or Python 3.12), `ruff`, `pre-commit`, Docker
      Desktop; then `pre-commit install --hook-type pre-commit --hook-type commit-msg`.
- [ ] **HUMAN H3** — GitHub settings: secret scanning + push protection, Dependabot alerts, private
      vulnerability reporting, "require approval for workflows from outside contributors".
- [ ] **HUMAN H4** — Run `scripts/setup-branch-protection.sh` after M0.2 merges.
- [ ] **HUMAN H5** — Create the bot Instagram account (Creator), a Meta developer app with the Instagram
      product (Instagram Login), add your personal account as a tester.
- [ ] **HUMAN H6** — Create Supabase projects `insta-saver-dev` and `insta-saver-prod`; add their
      credentials to GitHub Environments `staging` and `production` (never to the repo).

- Owner: architect · Branch: `docs/m0-contracts-v0` → PR into `dev` · Labels: `M0`, `area:contracts`

- [ ] status

### M0.2 — CI, tooling, branch protection script
- Owner: devops-engineer · Branch: `chore/m0-ci-tooling` → PR into `dev` · Labels: `M0`, `area:devops`, `security`
- In scope: `Makefile` (targets: `dev`, `test`, `lint`, `fmt`, `process`, `process-prod` stub with the
  main/clean/tag check, `replay` stub); `.github/workflows/pr-checks.yml` (lint, typecheck, test, gitleaks —
  each job skips cleanly when its area doesn't exist yet); `.github/workflows/source-branch.yml`
  (`ci/source-branch`: PRs into `main` must come from `dev`, `release/*` or `hotfix/*`);
  `.github/dependabot.yml`; `scripts/setup-branch-protection.sh` (rulesets per AGENTS_PLAN.md §15.5,
  `gh api`, idempotent, dry-run flag); `pre-commit autoupdate`.
- Guardrails: workflows use `pull_request`, never `pull_request_target`; actions pinned by SHA; no secrets.
- Acceptance: workflows pass `actionlint` (or are validated by `gh workflow view` after push); the
  protection script prints what it would change with `--dry-run`.
- Depends on: nothing.
- [ ] status
